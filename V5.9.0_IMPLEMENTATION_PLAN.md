# MindCanvas v5.9.0 — implementation plan

## Scope lock

The release is split into independently verifiable milestones. Existing local
document storage remains explicitly local; no cloud storage, paid service,
credential, or production deployment is introduced by this release.

## Milestones

### A — PDF guide correctness

- Reproduce a DOCX-first document list with a PDF below it.
- Add typed document metadata to rows and guide events.
- Make the PDF guide target a PDF row and require a successful PDF viewer-ready
  event scoped to the selected document and guide session.
- Clean event listeners/timers on close, Back, guide change, and unmount.

### B — Local document library

- Keep the current document schema compatible and add a versioned local
  repository boundary.
- Add direct upload, multi-file progress, search/filter, download, rename and
  open-with-tool actions in Uploaded documents.
- Move guest binary persistence to IndexedDB with a guarded migration from the
  current guest localStorage records; retain a recovery path on quota failure.

### C — Canvas document picker

- Add a Documents panel in CanvasBoard that lists the shared repository,
  filters by type, previews the selected file and inserts a reference at the
  visible canvas center.
- Preserve one undo transaction per insertion and keep document ID plus
  revision ID on the embed. Deleting a canvas node must not delete the library
  record.

### D — Tools area and PDF editor

- Add Learning Hub → Tools with a dedicated PDF annotation page and the current
  annotation engine.
- Preserve embedded PDF fullscreen annotation rules while allowing the
  dedicated editor to work in its own page.
- Keep realtime strokes, eraser/highlighter, Ctrl+Z/Y, Space pan and Ctrl-wheel
  viewer zoom. Export a new PDF without mutating the source.

### E — DOCX compatibility spike and editor

- Verify import/edit/export round-trip against fixture DOCX files before
  exposing the editor as complete.
- Implement the committed basic Word feature matrix with a content model,
  autosave draft and valid DOCX export. Unsupported constructs remain in the
  source or produce an explicit warning and a new copy.
- Do not rename HTML to `.docx`; do not claim full Word parity.

### F — verification and release package

- Run unit/integration tests, browser E2E where available, typecheck and
  production build.
- Verify rendered PDF/DOCX outputs and reload them through the app.
- Update version/changelog only after required gates pass.
- Produce a changed-files-only ZIP rooted at `mindcanvas-v1/`.

## File plan

Initial files: `App.tsx`, `documentStore.ts`, `FolderManager.tsx`,
`DocumentViewer.tsx`, `CanvasBoard.tsx`, `LearningHubPage.tsx`,
`featureGuides.ts`, guide/component tests and `styles.css`. Add focused
repository/editor files only when their tests establish the contract. Update
the web package version, lockfile and service-worker cache together at the
release gate.

## Risks and blockers

- The current app stores data URLs locally. A true multi-device library needs a
  backend, storage bucket, quota policy and RLS design; it is a separate
  decision, not silently implemented here.
- Valid DOCX round-trip requires an OOXML writer. Mammoth is an importer/viewer,
  not a complete DOCX editor/exporter. A compatibility spike must pass before
  the editor is called complete; otherwise the release reports the blocker.
- Browser-only PDF/DOCX E2E and opening output in Word/LibreOffice may not be
  available in this environment. Those checks remain explicitly unverified
  until a browser/office fixture run is performed.
