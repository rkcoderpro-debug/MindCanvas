# MindCanvas v5.9.0 — báo cáo triển khai và nghiệm thu

## Trạng thái phát hành

Mã v5.9.0 đã được triển khai trong worktree và qua các gate tự động bên dưới. Chưa nên gọi là production release hoàn tất: browser E2E/screenshot UI bị chặn bởi môi trường (`ERR_BLOCKED_BY_CLIENT`) và DOCX editor chỉ cam kết ma trận cơ bản, chưa phải Microsoft Word parity. Không có cloud backend, public upload, credential mới hay dịch vụ trả phí nào được thêm.

## Những gì đã triển khai

### Thư viện tài liệu cục bộ

Quản lý thư mục có nút **Tải tài liệu lên**, upload nhiều file, giới hạn 40 MB/file, tìm kiếm, lọc loại, tải xuống, mở viewer và xóa. Mỗi record có `id`, `owner`, `kind`, MIME, kích thước, `folderId`, `updatedAt` và revision hiện tại. Giao diện ghi rõ dữ liệu được lưu trên thiết bị.

Kho dùng IndexedDB `mindcanvas-documents-v1`, schema version 2 và index owner. Khi tạo object store lần đầu, record guest cũ từ `mindcanvas:documents:guest` được copy vào IndexedDB; nếu mở/ghi IndexedDB thất bại, guest vẫn đọc/ghi được đường localStorage cũ. Account khác không đọc được record của nhau. Migration không xóa dữ liệu cũ nên có thể retry; xóa tài liệu chỉ xóa record thư viện, không xóa canvas/project.

### Chèn tài liệu vào canvas

Canvas có panel **Tài liệu đã tải lên**, tìm kiếm/lọc PDF, DOCX, PPTX hoặc XLSX, và chèn file được chọn vào tâm vùng canvas đang nhìn thấy. Embed mới chỉ lưu `documentId` và `revisionId`; bytes dùng chung từ repository khi render. Xóa node canvas không xóa file thư viện. Nếu repository không mở được, canvas giữ đường fallback data URL để không làm mất thao tác hiện tại và hiển thị lỗi lưu; đây là đường phục hồi, không phải storage mới trong localStorage.

Embed cũ chứa data URL vẫn parse được. Embed tham chiếu đã mất khỏi thư viện hiển thị cảnh báo thay vì crash hoặc tự tìm dòng đầu.

### PDF editor

Learning Hub → **Công cụ** → **Vẽ trên PDF** dùng cùng `DocumentViewer`/annotation engine với viewer hiện có. PDF embedded vẫn chỉ cho vẽ khi bật fullscreen; dedicated editor cho phép vẽ ngay trên trang công cụ. Pen, highlighter và eraser vẽ realtime; eraser xóa theo stroke; có kích thước bút/tẩy, undo/redo, Ctrl+Z/Y khi fullscreen, Space pan và xuất thành file `*-annotated.pdf` mới. PDF gốc không bị ghi đè.

Ctrl/Meta + wheel chỉ zoom khi con trỏ ở vùng PDF và gọi `preventDefault()` để không zoom trang web. Nút `-`/`+` đặt zoom origin ở tâm viewport hiện tại; Ctrl + kéo đặt origin ở vị trí bắt đầu của pointer. PDF.js worker được trỏ tới asset Vite phát hành để tránh lỗi `No "GlobalWorkerOptions.workerSrc" specified`.

Viewer đọc DOCX qua Mammoth, PPTX qua OOXML slide text và XLSX qua SheetJS trong cùng thư viện. Đây là viewer; PPTX/XLSX chưa có editor.

### DOCX editor

Learning Hub → **Công cụ** → **Soạn thảo DOCX** → chọn file. Import dùng Mammoth thành semantic HTML đã sanitize; chỉnh sửa trong contentEditable với đoạn, Heading 1–3, bold, italic, underline, highlight, cỡ chữ và bullet list. Draft HTML được debounce vào localStorage theo owner + document ID để phục hồi khi reload; không lưu bản nhị phân mới ở localStorage.

**Lưu bản mới** và Ctrl+S tạo file DOCX mới; bản gốc giữ nguyên. Writer OOXML bằng JSZip tạo các part `[Content_Types].xml`, relationships, styles, numbering và `word/document.xml`, không đổi HTML thành file giả đuôi `.docx`. Output fixture đã mở bằng LibreOffice và render được PDF/PNG.

#### Ma trận tương thích DOCX

| Hạng mục | Trạng thái v5.9.0 | Ghi chú nghiệm thu |
|---|---|---|
| Paragraph, line break | Hỗ trợ | Giữ text và xuống dòng cơ bản |
| Heading 1–3 | Hỗ trợ | Xuất paragraph style OOXML |
| Bold/italic/underline | Hỗ trợ | Xuất `w:b`, `w:i`, `w:u` |
| Highlight | Hỗ trợ cơ bản | Màu CSS được quy đổi sang `w:shd` |
| Font size | Hỗ trợ cơ bản | CSS px/pt và legacy font size |
| Bulleted list | Hỗ trợ cấp 1 | Có numbering part hợp lệ |
| Tables, images, links | Chưa round-trip | Mammoth warning; bản gốc vẫn an toàn |
| Header/footer, section, columns, fields, comments, track changes, complex styles | Chưa hỗ trợ | Không tuyên bố parity với Word |
| PPTX/XLSX editing | Chưa hỗ trợ | Chỉ viewer đọc trong v5.9.0 |

Phương án compatibility spike đã kiểm tra dependency tại thời điểm triển khai: Mammoth `1.12.3` (BSD-2-Clause), JSZip `3.10.2` (MIT hoặc GPL-3.0-or-later), PDF.js `6.3.289` (Apache-2.0), pdf-lib `1.17.1` (MIT), SheetJS `0.18.5` (Apache-2.0). Mammoth được tài liệu chính thức mô tả là chuyển DOCX sang semantic HTML và các tài liệu phức tạp có thể không chuyển hoàn hảo; vì vậy editor dùng writer OOXML riêng và hiển thị warning thay vì giả vờ hỗ trợ Word đầy đủ.

### Guide và lỗi PDF/DOCX

#### Nguyên nhân tái hiện

Regression test dựng `.document-file-table` với DOCX đứng trước PDF. Bản cũ dùng selector dòng file chung và action `documents:open`; một event mở DOCX có thể làm guide PDF tiến bước dù PDF chưa được chọn. Đây là lỗi định tuyến sự kiện/target, không kết luận là PDF.js đọc nhầm bytes.

#### Cách vá

- Row có `data-document-id` và `data-document-kind`; guide PDF target đúng `.file-row[data-document-kind="pdf"]`.
- Mở PDF phát `documents:open:pdf`, còn tài liệu khác phát action tổng quát.
- `DocumentViewer` phát `viewer-ready` chỉ sau `getDocument(...).promise` resolve (Office viewer cũng phát ready sau parse thành công), kèm `documentId`, `kind`, `viewerSessionId`.
- Mỗi overlay có `guideSessionId`; action từ session cũ bị bỏ qua. Manager cleanup session/listener/timer khi đóng, skip, đổi route hoặc unmount.
- Guide `document-tools` mở đúng route Learning Hub khi chạy từ Wiki; guide không cho qua bước nếu target thiếu hoặc action thật chưa xảy ra.
- Spotlight làm sáng toàn vùng control; con trỏ animation nằm ngoài vùng đang chỉ. Popover practice không khóa phần việc người dùng; bước canvas yêu cầu chọn giữ hoặc thùng rác. Nút `?` chỉ render sau khi guide tương ứng có trạng thái `completed`.

## Hướng dẫn dùng theo 4 luồng

1. **Upload thư viện:** Mở **Quản lý thư mục → Tài liệu đã tải lên → Tải tài liệu lên**, chọn một hoặc nhiều PDF/DOCX/PPTX/XLSX. Dùng tìm kiếm/lọc; bấm dòng hoặc con mắt để viewer, tải xuống để lấy bản gốc, hoặc xóa record.
2. **Chèn canvas:** Mở canvas → nút **Tài liệu đã tải lên** trên toolbar → lọc/tìm file → bấm file. Embed xuất hiện tại tâm viewport. Di chuyển/xóa node như phần tử canvas; file gốc vẫn ở thư viện.
3. **PDF editor:** Learning Hub → **Công cụ → Vẽ trên PDF** → chọn PDF. Bật **Vẽ trên PDF** (viewer embedded trong Quản lý thư mục vẫn cần fullscreen), chọn pen/highlight/eraser, giữ E để tẩy tạm thời, Ctrl+Z/Y để undo/redo, Ctrl-wheel để zoom quanh pointer, rồi **Xuất PDF** để tạo bản mới.
4. **DOCX editor:** Learning Hub → **Công cụ → Soạn thảo DOCX** → chọn DOCX. Sửa nội dung, dùng toolbar định dạng hoặc Ctrl+S để **Lưu bản mới**. File gốc không đổi; nếu Mammoth cảnh báo phần không hỗ trợ, kiểm tra bản copy và tải xuống để mở trong Word/LibreOffice.

## Migration, khôi phục và rollback

- **Document store:** mở DB version 2 là migration additive. Record guest cũ được copy, localStorage cũ không bị xóa; retry sau lỗi quota không mất nguồn. Account owner được ghi vào record và kiểm tra khi đọc.
- **Canvas:** board validator chấp nhận cả embed data URL cũ và reference mới. Khi thiếu repository record, UI cảnh báo. Không có thao tác migration nào xóa project/canvas thật.
- **Guide:** `GUIDE_CONTENT_VERSION = v5.9` tạo namespace tiến trình mới để các guide strict mới không bị trạng thái cũ giả hoàn thành. Reset admin chỉ xóa entry guide; không đụng document/project.
- **DOCX:** autosave chỉ là draft HTML theo document ID. Lưu/xuất luôn tạo bytes mới; không ghi đè nguồn.
- **Rollback:** lưu bản sao `mindcanvas-documents-v1`/localStorage trước khi thử nghiệm; khôi phục commit/file ZIP v5.8.1, giữ DB vì schema additive. Nếu cần quay lại code cũ, record v2 có thể tiếp tục đọc bằng fallback ứng dụng mới; không chạy migration destructive.

## Blocker còn lại

1. Cần chạy lại browser E2E trên môi trường cho phép truy cập preview localhost và chụp screenshot trước/sau của guide + PDF/DOCX editor.
2. Cần quyết định riêng nếu muốn DOCX round-trip parity cao hơn: phải thêm OOXML model/writer cho tables/images/headers/fields hoặc tích hợp editor có license phù hợp; không thể đạt an toàn bằng Mammoth viewer.
3. Multi-device/cloud document library cần backend, bucket, quota/RLS và quyền chia sẻ; v5.9.0 cố ý chưa triển khai phần này.

## Lệnh áp dụng

```bash
cd mindcanvas-v1
npm ci
node node_modules/typescript/bin/tsc --noEmit -p apps/web/tsconfig.json
node node_modules/vitest/vitest.mjs run apps/web/src --testTimeout=15000
cd apps/web && node ../../node_modules/vite/bin/vite.js build
```

ZIP bàn giao chỉ chứa các path trong `CHANGED_FILES_V5.9.0.txt`, vẫn giữ prefix `mindcanvas-v1/`; không gồm `node_modules`, `dist`, cache, secrets hoặc `.env`.
