# MindCanvas V4.4 — Chia sẻ và cộng tác

V4.4 cho phép chủ project mời người khác bằng email. Người được mời có thể mở cùng canvas; quyền `editor` được thêm/sửa/xóa nội dung, quyền `viewer` chỉ xem. Thay đổi đã lưu được truyền qua Supabase Realtime Postgres Changes. Mỗi người vẫn có viewport, timer, streak, quota AI và dữ liệu học riêng.

## Kế hoạch triển khai V4.4

1. **Dữ liệu và bảo mật:** thêm thành viên, lời mời có thời hạn, nhật ký hoạt động; mọi truy cập note/tài liệu đi qua RLS; database chỉ lưu SHA-256 của token.
2. **Luồng chia sẻ:** chủ project tạo link theo email và quyền `editor`/`viewer`, có thể đổi quyền, xoá thành viên hoặc thu hồi link.
3. **Cộng tác:** project được chia sẻ xuất hiện trong **Shared with me**; thay đổi đã lưu đồng bộ qua Postgres Changes, còn mỗi người giữ viewport riêng.
4. **An toàn thao tác:** editor dùng cùng autosave/revision lock hiện có; nếu hai thay đổi xung đột, hộp phục hồi cloud/local/copy vẫn được dùng. Viewer chỉ pan/zoom, export và đọc nội dung.
5. **Kiểm thử và phát hành:** chạy test, typecheck, build; áp migration trước khi deploy; kiểm tra hai tài khoản rồi push commit lên `main`.

## 1. Cài bản vá vào repo hiện tại

1. Tải ZIP V4.4 và giải nén vào thư mục repo MindCanvas.
2. Giữ nguyên cấu trúc thư mục, chọn ghi đè khi Windows hỏi.
3. Không chép đè các file `.env`.
4. Mở PowerShell/Git Bash tại thư mục repo và kiểm tra:

```bash
git status
```

Nếu repo đang có thay đổi riêng chưa commit, hãy commit hoặc sao lưu chúng trước khi chép bản vá.

## 2. Chạy migration Supabase

Mở Supabase Dashboard → **SQL Editor** → **New query**. Mở file:

```text
supabase/migrations/0011_v4_4_collaboration.sql
```

Dán toàn bộ nội dung vào SQL Editor rồi bấm **Run** một lần. Migration tạo bảng thành viên/lời mời, RPC bảo vệ token, RLS cho note và tài liệu, đồng thời bật `notes` cho Realtime.

Nếu dự án dùng Supabase CLI đã liên kết, có thể chạy thay thế:

```bash
supabase db push
```

Không bỏ qua migration. Nếu chưa chạy, nút Chia sẻ sẽ báo lỗi vì các RPC V4.4 chưa tồn tại.

## 3. Kiểm tra local trước khi push

Tại thư mục repo chạy lần lượt:

```bash
npm install
npm run typecheck
npm test
npm run build
```

Kết quả mong đợi:

- Web typecheck không lỗi.
- Server typecheck không lỗi.
- Toàn bộ test web/server đều đạt.
- Build tạo được `apps/web/dist` và `apps/server/dist`.

## 4. Commit và push lên GitHub

Mã commit được Git tự sinh; không cần tự tạo hoặc nhập mã commit. Dùng các lệnh sau:

```bash
git status
git add -A
git diff --cached --stat
git commit -m "feat: shared collaborative projects v4.4"
git pull --rebase origin main
git push origin HEAD:main
```

`git push origin HEAD:main` đẩy đúng commit/nhánh hiện tại lên `main`, kể cả khi local đang đứng ở tên nhánh sửa lỗi. Không dùng `git push --force`.

Sau khi push, vào Render → service web → **Manual Deploy** → **Deploy latest commit** nếu Render chưa tự bắt đầu. Giữ build command hiện tại:

```bash
npm install && npm run build --workspace apps/web
```

## 5. Kiểm thử tính năng share

1. Đăng nhập tài khoản A và mở một project đã lưu cloud.
2. Bấm **Share project**, nhập đúng email Google của tài khoản B, chọn `Can edit` hoặc `Can view`, rồi tạo link.
3. Mở link bằng cửa sổ trình duyệt khác hoặc thiết bị khác, đăng nhập đúng email B và chấp nhận lời mời.
4. Tài khoản B sẽ thấy file trong **Shared with me**. Hai cửa sổ mở cùng canvas.
5. Với `Can edit`, thêm một node hoặc text ở B rồi chờ trạng thái lưu. Thay đổi sẽ xuất hiện ở A.
6. Với `Can view`, kiểm tra toolbar chỉnh sửa bị ẩn và thay đổi nội dung không được lưu.
7. Quay lại Share ở A để đổi quyền, xoá thành viên hoặc thu hồi lời mời.

Link mời chỉ chấp nhận đúng email đã nhập và hết hạn sau 7 ngày. Token thô chỉ nằm trong link; database lưu SHA-256 của token.

## 6. Nếu push bị hỏi đăng nhập

GitHub không nhận mật khẩu tài khoản cho Git over HTTPS. Dùng GitHub Desktop hoặc Personal Access Token khi Git yêu cầu Password. Remote hiện tại:

```text
https://github.com/rkcoderpro-debug/MindCanvas.git
```

Nếu `git pull --rebase` báo conflict, giữ bản thay đổi cần thiết, chạy `git add -A`, `git rebase --continue`, sau đó lặp lại `git push origin HEAD:main`. Không force-push.
