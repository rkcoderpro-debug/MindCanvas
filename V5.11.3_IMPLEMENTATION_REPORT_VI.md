# Báo cáo triển khai v5.11.3

## Lỗi đã xác định

Hàm `public.learning_bump_version()` trong migration `0018_v4_9_learning_shares.sql` được dùng cho ba bảng. Khi trigger của `flashcards` chạy, biểu thức `old.questions` tham chiếu đến trường không tồn tại trong bản ghi flashcard và tạo lỗi PostgreSQL `42703`.

## Mã đã thay đổi

- `supabase/migrations/0018_v4_9_learning_shares.sql`: sửa cài đặt mới để dùng ba trigger function riêng.
- `supabase/migrations/0021_v5_11_3_learning_version_trigger_fix.sql`: sửa các database đã áp dụng `0018`, xóa trigger cũ và cài lại trigger đúng bảng.
- Tăng phiên bản web/server lên `5.11.3`, cập nhật cache Service Worker.
- Badge trong sidebar và thông tin chẩn đoán AI lấy từ `apps/web/package.json` qua `apps/web/src/lib/appVersion.ts`, tránh lệch phiên bản do hardcode.
- API health trả `release: 5.11.3`.
- Giữ xử lý lỗi cloud/localStorage của v5.11.2.

## Cách áp dụng trên Supabase

1. Sao lưu hoặc xác nhận trạng thái migration hiện tại.
2. Chạy toàn bộ `0021_v5_11_3_learning_version_trigger_fix.sql` trong Supabase SQL Editor.
3. Kiểm tra ba trigger `learning_quiz_version`, `learning_card_version`, `learning_lab_version` trỏ đến đúng function.
4. Thử sửa mặt trước/mặt sau flashcard và tải lại trang để xác nhận dữ liệu đã lưu.
5. Thử sửa Quiz và Lab để xác nhận `content_version` vẫn tăng đúng.

Migration mới có `drop trigger if exists`, `create or replace function` và `drop function if exists`, nên có thể chạy lại an toàn sau khi kiểm tra lỗi.

## Giới hạn xác nhận

Chưa kết nối trực tiếp đến project Supabase production trong môi trường này. Build và test frontend không thay thế cho việc chạy migration và kiểm thử trên database thật.
